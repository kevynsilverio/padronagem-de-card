# Atualização de cards de QA e Desenvolvimento

Nova padronização dos cards para aumentar a rastreabilidade, reduzir retrabalho e alinhar **PO**, **Desenvolvimento** e **Qualidade**.

Esta documentação descreve a proposta de melhoria no fluxo **DEV → QA**: quais campos passam a ser obrigatórios, quando a justificativa é exigida e como preencher cada card.

## O que muda

| Card | O que muda |
| --- | --- |
| **Desenvolvimento** | Os campos atuais continuam. No fechamento da implementação entram 5 campos novos. |
| **QA** | Os campos atuais continuam. Na validação entram 3 campos novos. |

## Novos campos em resumo

**Desenvolvimento**

- Resumo da implementação
- Como validar / reproduzir
- Critérios de aceite atendidos? (`Sim` / `Parcial` / `Não`)
- Regra de negócio aplicada na validação
- Justificativa (obrigatória quando for `Parcial` ou `Não`)

**QA**

- Ambiente / Versão validada
- Critérios de aceite validados? (`Sim` / `Parcial` / `Não`)
- Justificativa (obrigatória quando for `Parcial` ou `Não`)
